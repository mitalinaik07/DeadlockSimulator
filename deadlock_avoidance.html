DEADLOCK AVOIDANCE: BANKER'S ALGORITHM
Purpose

To avoid deadlock. It checks whether allocating resources to a process will keep the system in a safe state.

1. Basic Rules
  1. Need = Maximum − Allocation
  2. Available = Total Resources − Allocated Resources
  3. A process can execute only if its Need ≤ Available for every resource type.
  4. If a process can execute, it finishes and releases its allocated resources.
  5. The released resources are added to Available.
  6. Repeat the process until all processes finish or no process can proceed.
2. Safe State and Unsafe State
  • Safe State: All processes can finish in some order. A safe sequence exists.
  • Unsafe State: A safe sequence cannot be guaranteed. The system may potentially enter a deadlock.
  • Deadlock Avoidance: Grant a resource request only if the resulting state remains safe.
3. Resource Request Conditions

When a process requests additional resources:

  1. Request ≤ Need — The process cannot request more than its declared maximum.
  2. Request ≤ Available — The requested resources must currently be available.
  3. Temporarily allocate the resources and update the matrices.
  4. Run the safety algorithm.
  5. If the state is safe, grant the request.
  6. If the state is unsafe, deny or postpone the request and restore the previous state.
4. Important Formulas
Term Formula
Need Maximum − Allocation
Available Total Resources − Total Allocated Resources
Temporary Available Available − Request
New Allocation Allocation + Request
New Need Need − Request
