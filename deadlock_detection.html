DEADLOCK THEORY & RULES
DEADLOCK DETECTION OVERVIEW

A deadlock occurs in an operating system when a set of processes are blocked because each process holds a resource and waits for another resource held by another process in the set.

1. Resource Allocation Graph (RAG)

Purpose: Detect deadlocks by mapping relationships between processes and resources.

Basic rules:

  • Process: Circle node ($P$)
  • Resource: Square node ($R$)
  • Request edge: $P \rightarrow R$
  • Allocation edge: $R \rightarrow P$
  • Cycle rule:
    • No cycle → No deadlock
    • Single-instance cycle → Deadlock
    • Multi-instance cycle → Possible deadlock
2. Tarjan's Algorithm (SCC)

Purpose: Detect cyclic dependencies between processes using DFS on a Wait-For Graph.

Basic rules:

  • DFS traversal from unvisited process nodes.
  • Track discovery index ($dfn$) and low-link values ($low$).
  • Maintain node stack during active traversal.
  • Identify SCC when $dfn[u] == low[u]$.
  • Cycle rule:
    • No cyclic SCC → No deadlock
    • Cyclic SCC (Single-inst.) → Deadlock
    • Cyclic SCC (Multi-inst.) → Possible deadlock
